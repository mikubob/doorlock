## 未升级数据库的顺序

1. 选中后端实际连接的数据库，保存完整备份，停止所有后端实例和排程写入。
2. 运行 01，核实原表结构、数据范围、InnoDB 引擎和绑定来源。
3. 按文件顺序在同一连接运行 02；任何 SQL 错误或 STOP 提示立即停止并核对已执行部分。
4. 运行 03。缺失字段应为 0 行；核对类型/NULL/default、唯一索引、状态行，以及绑定和任务复核结果，再启动后端。

02 合并了最初迁移和现场续补的有效逻辑：跳过已经存在的新增列和同名索引，保留既有状态、课程键、调整、来源和绑定。它不修正未知的历史字段定义，不重置覆盖，不自动转换零次任务，不发设备指令。已有新增表结构不完整时由 03 明确列出缺项，不能因为 CREATE TABLE IF NOT EXISTS 成功就忽略核验。

跨表 SN/JSH 使用 BINARY 精确分组与关联，避免现库排序规则差异；只采用唯一非空编号。歧义和缺失绑定须人工核实。已有容量数值保持原值，历史 SN 丢失的前导零不能由类型转换恢复。

04 只停用任务，不删除字段/表/审计，不恢复物理动作，不替代数据库备份恢复。正常升级顺序不包含 04。

原日期版本及报错续跑的临时 SQL 已删除，其必要逻辑保留于 02、03，不再维护多份运行顺序。实施及测试记录见 [课表联动整改实施与验证记录](../../../../doc/todo/课表联动整改实施与验证记录-2026-10-05.md)。
