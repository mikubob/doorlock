## 需要拆分的组件

### Excel 导入与 HTTP 导出

原 `soft_service/service.utils.ExcelUtils` 拆为：

- `soft_service/service.excel.TaskExcelImportService`：任务模板导入，保留项目锁、冻结校验及 READ_COMMITTED 事务。
- `soft_service/service.excel.CourseExcelImportService`：课程模板导入。
- `soft_service/service.excel.CheckResultExcelImportService`：巡查模板导入及行级回执，保留读取全部工作表与事务落库流程。
- `soft_service/service.excel.UserExcelImportService`：用户模板导入，保留 TransactionTemplate 边界。
- `soft_service/service.excel.StudentInfoExcelImportService`：学生信息导入。
- `soft_main/export.ExcelResponseExporter`：将导出数据写入 HTTP 响应，保留原文件名、表头、列映射和输出流行为。

原 `soft_main/utils.ReadExcelUtils` 拆为：

- `soft_common/utils.ExcelWorkbookUtils`：工作簿读取和单元格转换，无业务模型依赖。
- `soft_service/service.excel.TaskExcelPreviewService`：旧任务模板预览入口。
- `soft_service/service.support.StudentScorePreviewService`：旧演示接口的学生成绩预览，保留随机成绩规则。

旧任务预览的解析实现原本返回空列表，本次保留该行为，没有启用已注释的旧映射逻辑；真实任务导入仍使用 TaskExcelImportService。

### 项目任务树和文件清理

- `service.utils.TaskTreeUtils` 只保留纯内存辅助方法；数据库查询与项目信息补充移入 `soft_service/service.support.ProjectTaskTreeSupport`。原有树构建和计数行为保留。
- 原 `config.ClearFileConfig` 的文件操作移入 `soft_service/service.support.EvidenceFileCleanupService`；任务入口为 `soft_main/job.EvidenceFileCleanupJob`。
- 清理任务没有新增自动调度，默认仍不执行清理。`file.cleanup.enabled` 默认 false；显式启用后调用任务入口才执行清理。

### 门禁通讯和状态写入

- `soft_service/service.gateway.SmartLockGateway` 定义设备通讯边界。
- `soft_main/smartlock.client.SmartLockClient` 实现边界，集中门禁 SDK 通讯，不访问数据库。
- `soft_service/service.support.SmartLockStateService` 在通讯成功后更新指定锁的状态。
- 控制器和 Quartz Job 注入通讯边界，不再手动创建 SmartLockSwitch，也不再共享静态锁状态。

DoorAccessIO SDK 仍由 soft_main 依赖，soft_service 只依赖通讯接口，避免产生反向模块依赖。

状态查询返回的 Future 现在跟随 SDK 回调完成；原实现提交命令后即返回旧状态，本次改为等待通讯结果并完成状态回写。失败的设备仍返回原锁信息，不因单个设备失败中断整批查询。

## UserVo 与 ProjectItemVo 的输入输出拆分

`UserVo` 保留为输出对象，移除输入校验和主键映射注解，输出字段不变。修改联系方式使用 `params.UserEditParam`，只接收该操作需要的字段，保留 userName、email、phone 的原有校验；实际被修改的用户仍由认证身份确定。

`ProjectItemVo` 保留为查询结果对象；请求分为：

- `params.ProjectItemSaveParam`：分类和子项维护，保留原维护请求字段。
- `params.ProjectItemImportParam`：选中子项导入，只保留 id、projectId；评分字段仍从数据库重新读取，客户端继续提交旧对象的额外字段也能正常绑定。

Controller、Service 接口和实现已同步改用对应请求类型，Mapper 查询返回类型继续使用 ProjectItemVo。
