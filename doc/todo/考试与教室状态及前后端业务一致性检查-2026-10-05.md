## 2. 考试、教室状态与课程

### B01｜考试中仍显示空闲，且污染空闲统计与筛选（P1）

**问题与证据**

- [前端 2D 页面](D:/CodingFiles/School/assessment-front/assessment-front/src/views/digitaldoor2d/index.vue:378) 的 `formatClassrooms` 用 `const isActive = !!activeCourse`，仅附加 `exams`，没有推导当前考试占用。
- 模板第 99–109、128–129 行，`getStats` 第 210–220 行，`isVisibleByFilter` 第 460–462 行，`floorSummary` 第 468–471 行，都依赖课程布尔值 `isActive`。
- 第 447–449、473–475 行只把考试用于颜色和考试筛选。因此同一间教室可以同时“黄色考试高亮”“空闲”“使用率 0%”。

**解决方案**

统一输出教室状态，例如 `idle / teaching / examining / unknown`，并另外保留未来预约字段。当前有效考试应推导为 `examining`；没有当前考试再判断课程。课程与考试同时发生时应报告冲突，不能仅靠展示优先级掩盖排程问题。卡片、弹窗、楼层汇总、总览和筛选统一使用该状态。将“上课中”“考试中”“空闲”分别统计；教室使用率按当前被课程或考试占用的教室数计算。考试人数没有来源时显示“未知”，不伪造人数。

**验收场景**：固定当前时间为 `2026-10-05 01:05:30`，添加附图时段的考试；教室显示“考试中”，不进入空闲筛选，考试中数量和使用率增加，结束后恢复合理状态。

### B02｜未来预约与正在考试混用一个判断函数（P2）

**问题与证据**

[考试工具](D:/CodingFiles/School/assessment-front/assessment-front/src/util/exam.js:18) 的 `selectDisplayExam` 先找进行中的考试，没有则返回最近未来考试；2D 的 `hasActiveExam` 直接判断其返回值。该函数用于班牌预告尚有合理性，用于“当前活动考试”则不准确。五天后的预约也会让教室黄色高亮，课程中的教室也可能被未来考试颜色覆盖。

**解决方案**

拆分 `getCurrentExam`、`getNextExam` 和班牌展示选择器。当前考试须满足 `start <= now < end` 且未被取消/提前结束；未来预约单独显示预约标识或预约列表。保持“未来有预约”与“此刻被占用”两个独立维度，筛选名称明确说明含义。

**验收场景**：今天空闲但五天后有考试，当前占用为“空闲”，可以显示预约标识；开始时切换“考试中”，结束时移除当前占用。

### B03｜考试持久化状态不会随时间自动变化（P2）

**问题与证据**

[考试控制器](D:/CodingFiles/School/assessment-back-v2/assessment/soft_main/src/main/java/com/hnkjzyxy/ab/controller/ExamController.java:123) 新增默认 `status=0`；状态修改接口只有人工更新。检查考试服务及现有 job/init 未发现按起止时间推进考试状态的实现。[批量管理组件](D:/CodingFiles/School/assessment-front/assessment-front/src/components/ExamBatchManager.vue:25) 直接用持久化状态显示“未开始/进行中/已结束”，班牌选择器却用时间判定并仅排除 `2`。因此同一场考试可以在班牌被展示，管理表仍显示“未开始”；时间早已结束的记录也可能一直为 `0`。

**解决方案**

区分管理员控制的业务状态（有效、取消、提前结束等）和时间推导状态（未开始、进行中、已结束）。推荐接口返回 `effectiveStatus` 与服务器时间，管理列表和教室状态统一使用该推导结果。如果必须落库维护时间状态，则增加幂等同步、启动补偿和查询兜底，明确手动提前结束后的行为；不要只在新增时设置一次状态。

**验收场景**：未来、当前、过期考试的列表文字、教室状态、班牌展示一致；人工结束当前考试后不再占用。

### B04｜“实时”页面重算旧快照，加载失败仍可能显示空闲（P1）

**问题与证据**

- [2D 定时器](D:/CodingFiles/School/assessment-front/assessment-front/src/views/digitaldoor2d/index.vue:286) 每秒更新时钟，只在 `getSeconds()===0` 时重算已有 `lastCourses/lastExams`，没有周期拉取。另一个窗口新增、删除、调整考试或后端同步课表，当前窗口不会主动获知。
- 第 323–328 行查询失败保留最近成功快照；初次课表或考试失败时快照为空，教室仍可能被展示为“空闲”。已有错误提示是有价值的，但不能把未知占用继续统计为空闲。
- [班牌课表加载](D:/CodingFiles/School/assessment-front/assessment-front/src/views/eboard/index.vue:435) 同一天内也缺少周期更新。跨日请求失败后 `loadedCourseDate` 已被设置为当天，不会仅靠跨日逻辑继续重试。

**解决方案**

采用只读轮询或 SSE/WebSocket 订阅，配合页面重新可见时刷新、查询版本号、防重入和失败退避。为每个数据源记录读取时间与新鲜度；加载失败或超期时显示 `unknown`/“数据待刷新”，不能据此认定空闲。用实际经过时间或下一状态边界调度重算，避免依赖必须恰好命中整分钟的定时器。写操作保持显式触发，轮询不调用同步写接口。

**验收场景**：A 窗口修改考试，B 窗口在约定延迟内更新；考试/课表查询失败时出现未知状态；后台挂起恢复后状态及时更新。

### B05｜日期使用上海时区，课程时分和考试解析却使用本地时区（P2，条件性）

**问题与证据**

[日期工具](D:/CodingFiles/School/assessment-front/assessment-front/src/util/courseSchedule.js:1) 按 `Asia/Shanghai` 筛选日期；2D 第 380 行及 `isCurrentTimeInPeriod` 按浏览器本地时分判断；[考试工具](D:/CodingFiles/School/assessment-front/assessment-front/src/util/exam.js:20) 用没有时区的日期字符串构造 `Date`。班牌时钟第 651 行显式显示上海时间，考试倒计时却按本地解析。非上海时区终端上，“显示的时钟”“今天的课表”“正在考试”可能不同步。

**解决方案**

约定学校业务时区为 `Asia/Shanghai`。后端返回明确时区的 ISO 时间或 epoch 毫秒，同时返回服务器当前时间；前端显示与比较分别处理，禁止用无时区字符串隐式解析。课程日期加节次转换成学校时区的明确时间区间。用 UTC 与上海时区终端分别验证同一瞬间的状态一致。

### B06｜课程节次解析不一致，课间或部分节次状态错误（P1）

**问题与证据**

[2D 时段映射](D:/CodingFiles/School/assessment-front/assessment-front/src/views/digitaldoor2d/index.vue:330) 把 `1-4` 直接映射为 `08:20-11:50`；[班牌课表展开](D:/CodingFiles/School/assessment-front/assessment-front/src/views/eboard/index.vue:444) 拆成 `08:20-09:55` 与 `10:15-11:50`。10:00 时，两页面会分别判断“上课中”和“暂无课程”。两个实现只有奇数开始、偶数结束的映射；单节 `1` 或 `2-3` 等格式不能正确显示。后端手动新增没有要求有效 `classPeriod`，OA 转换也未校验节次格式。

**解决方案**

建立完整的逐节作息表及共享解析器，支持业务允许的单节、连续节、多段节次。明确课间是继续占用还是可借用，并让 2D、班牌、排程冲突校验采用同一规则。非法/未知节次在写入时拒绝或标为待处理，展示端显示未知而不是空闲。结束边界统一按秒计算，不继续以整分钟的 `<=` 误延长占用。

**验收场景**：`1-2`、`1-4`、单节、非成对节次、课间、结束瞬间均有确定且跨页面一致的行为；不支持的格式得到明确提示。

### B07｜考试与课程没有统一的占用冲突校验（P1）

**问题与证据**

[考试新增/修改](D:/CodingFiles/School/assessment-back-v2/assessment/soft_main/src/main/java/com/hnkjzyxy/ab/controller/ExamController.java:102) 及 [考试批量服务](D:/CodingFiles/School/assessment-back-v2/assessment/soft_service/src/main/java/com/hnkjzyxy/ab/service/impl/ExamServiceImpl.java:95) 仅查询 `sys_exam`，不检查 `sys_course_schedule`。[课表保存/更新](D:/CodingFiles/School/assessment-back-v2/assessment/soft_service/src/main/java/com/hnkjzyxy/ab/service/impl/CourseScheduleServiceImpl.java:134) 直接写入，课表整体同步也没有输出与已安排考试的占用冲突。

**解决方案**

按稳定的教室 ID 汇总课程和考试占用，将节次转换成日期时间区间后统一校验。正常排考拒绝课程冲突并返回冲突课程及时间；考试替代课程必须走明确的停课/调课或授权覆盖流程。OA 新课表同步发现冲突时生成冲突清单和处理状态，避免悄悄形成双重占用。

**验收场景**：在正常上课时段安排考试被拒绝；有授权的课程替代留下审计；同步课表引入新冲突时可见并可处理。

### B08｜“先查冲突、后插入”无法阻止并发重复排考（P1）

**问题与证据**

[考试控制器](D:/CodingFiles/School/assessment-back-v2/assessment/soft_main/src/main/java/com/hnkjzyxy/ab/controller/ExamController.java:102) 和 [批量服务](D:/CodingFiles/School/assessment-back-v2/assessment/soft_service/src/main/java/com/hnkjzyxy/ab/service/impl/ExamServiceImpl.java:95) 都先普通查询再写入。批量的 `@Transactional` 没有对同教室的排程资源加锁；[仓库考试 DDL](D:/CodingFiles/School/assessment-back-v2/assessment/soft_main/src/sql/sys_exam.sql:24) 也没有保证区间排他的约束。两个请求可以同时查到“无冲突”，随后都写入。

**解决方案**

所有单条、批量、修改入口进入同一个服务。在事务中锁定稳定的教室资源行，再查重叠区间并写入；多教室批量操作按固定 ID 顺序加锁，避免死锁。明确读隔离策略，锁后读取应能看到已提交的竞争写入。普通唯一索引无法表达任意区间不重叠，不应只增加 `(教室,开始时间)` 唯一索引就认为修复完成。

**验收场景**：两请求并发为同教室安排重叠考试，最多一个成功；不同教室不相互阻塞；批量失败按事务整体回滚。

### B09｜批量修改按旧快照判断冲突，合法互换时间被拒绝（P2）

**问题与证据**

[批量修改服务](D:/CodingFiles/School/assessment-back-v2/assessment/soft_service/src/main/java/com/hnkjzyxy/ab/service/impl/ExamServiceImpl.java:214) 仅排除当前行 ID，仍拿同批其他记录的旧安排校验。例如同教室 A 为 09:00–10:00、B 为 11:00–12:00；批量将两者交换，最终安排不重叠，但 A 的新时间与 B 的旧时间冲突，整批被拒绝。前端现有提示承认该限制，但没有解决业务能力问题。

**解决方案**

先合并本批全部记录的最终数据。与数据库校验时排除本批全部 ID，再对本批最终区间两两校验；在 B08 的事务资源锁下整体写入。拒绝重复 ID，明确同一 ID 不能在一批中有两个版本。

**验收场景**：合法换时/换教室一次提交成功；最终仍重叠的修改整批拒绝，并定位冲突行。

### B10｜单条、批量接口校验不统一，存在非法数据写入路径（P1）

**问题与证据**

- [单条更新](D:/CodingFiles/School/assessment-back-v2/assessment/soft_main/src/main/java/com/hnkjzyxy/ab/controller/ExamController.java:145) 虽计算合并后的时间，却未检查 `start < end`，也未检查空考试号、状态范围；没有其他考试时，倒置时间可以通过。仅修改某字段仍强制要求传 `boardSn`，与部分更新语义不一致。
- 新增与批量只用 `isAfter`，允许起止相等；[前端校验](D:/CodingFiles/School/assessment-front/assessment-front/src/util/exam.js:30) 则要求结束严格晚于开始。批量写入没有限制 `status` 必须为 0/1/2，也没有后端重复 ID 校验。
- 考试内容在仓库 SQL 为 `NOT NULL`，接口没有统一校验；直接 API 省略字段可能产生数据库异常，前端空字符串却能通过。

### B23｜数据库状态和 Quartz 注册/取消缺少一致性处理（P1）

### B24｜次数耗尽时没有 taskId，无法正确标记任务完成（P1）

拆分 `doorChannel`（校验范围的数字）与 `remarks`（描述）。通道来源为明确的设备绑定配置，任务创建时校验，不能到执行时才解析失败。统一循环次数契约，用 `unlimited` 与正整数 `maxExecutions/remainingExecutions` 表达；新建、列表、编辑、恢复与执行共用同一规则，并迁移旧记录。

**验收场景**：从新建页面创建合法通道的一次、三次和无限任务，均按计划执行；描述文本不进入通道参数。

## 5. 其他相关业务一致性

### B26｜历史巡查记录被写入当天请假人数，OA 匹配与空态不可靠（P1）

**问题与证据**

[巡查控制器](D:/CodingFiles/School/assessment-back-v2/assessment/soft_main/src/main/java/com/hnkjzyxy/ab/controller/ScheduleController.java:99) 不管新增还是编辑，都调用 `queryHotelDataByToday(resultVo.classes)`，随后覆盖 peopleLeave。[前端](D:/CodingFiles/School/assessment-front/assessment-front/src/views/patrolsentering/index.vue:262) 可以选择日期及编辑已有记录。因此补录昨日或编辑历史巡查可能写入今天的请假人数，而不是巡查当日、当节次的请假情况。

[OA 客户端](D:/CodingFiles/School/assessment-back-v2/assessment/soft_common/src/main/java/com/hnkjzyxy/ab/client/OaApiClient.java:157) 不传巡查日期；按 `className.contains(BJMC)` 每条匹配数据加 1。相似班级名会误匹配，空 BJMC 也会匹配所有非空班级；没有按学生去重或请假起止时间判定。响应 data 不是数组时直接返回 0，把格式异常当成“无人请假”。OA 当前返回是否保证一学生一条、仅包含当天有效请假，需要联调确认。

**解决方案**

按巡查日期和节次确定目标时间区间，调用支持历史条件的请假接口并按稳定班级 ID 精确匹配；按有效请假区间与学生 ID 去重。若 OA 不支持历史数据，保留历史已保存值或允许带来源的人工确认，不能用今天数据覆盖。区分“真实零人”和“来源未知/格式错误”，异常保留原值并给出可重试原因。

**验收场景**：昨日补录、历史编辑、相似班级名、空班级字段、重复请假记录、异常响应都不污染历史统计。

### B27｜考试与课表路径整体放行，写接口缺少业务权限控制（P1）

**问题与证据**

[SecurityConfig](D:/CodingFiles/School/assessment-back-v2/assessment/soft_main/src/main/java/com/hnkjzyxy/ab/config/SecurityConfig.java:134) 使用白名单 `permitAll`；[生产配置](D:/CodingFiles/School/assessment-back-v2/assessment/soft_main/src/main/resources/application-prd.yml:121) 与开发配置放行 `/courseSchedule/**`、`/exam/**` 及带 api 前缀的同类路径。考试新增、修改、删除、批量及状态接口和课表写入/同步接口没有方法级权限或调用者资源范围校验。为班牌查询开放路径时同时开放了业务修改能力。

这是业务完整性问题：页面有无按钮、班牌密码和前端正整数校验都不能阻止直接发请求修改排程。代码和配置可以确认该缺口，外部网关、有效 profile 以及真实部署访问结果未在本次验证。

**解决方案**

按具体路径和 HTTP 方法拆分公开只读查询与受保护的管理写操作。排考、修改状态、删除、同步课表需要服务端角色/权限及校区/教室范围校验；班牌使用设备身份读取其绑定教室数据。同步写操作改为有权限、可审计的明确动作。补齐操作者、目标教室、变更前后与结果的业务审计。

**验收场景**：匿名及无权限用户可以按规则读取班牌数据，但不能新增/修改/删除考试或修改/同步课表；授权管理用户只修改权限范围内资源。
