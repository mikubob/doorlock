# 课表联动整改实施与验证记录（2026-10-05）

本次按《课表联动的考试与教室状态业务一致性整改计划书》同步修改后端和 `D:\CodingFiles\School\assessment-front\assessment-front`。下表区分代码落地、已执行验证和必须联调的外部条件，不将单元测试视为实库并发或真实设备验收。

## 一、已落地的行为

- 考试单条、批量新增/修改、延长、换教室及重新启用共用事务服务。必须校验完整区间、目标教室与可信有效课表；不能覆盖课程、自动停课或绕过管理员校验。批量修改排除全部同批旧安排，再校验最终批次；行版本过期、重复 ID、空白内容及无效时间拒绝整批。任一写入影响行数异常抛出异常回滚。
- 课表同步、课程独立调整与考试共用数据库事务锁 `assessment:course_schedule:sync`，取得锁后再读正式业务数据。保留原 Redis 租约续期、提交前租约复查、分页截断/最小数量/收缩保护和事务内 DELETE + 批量写入，不采用 TRUNCATE。
- 课程获得独立稳定键 `courseKey`。本地课程、已办理停课/调课不会被全量同步清空。来源精确版本改变、多义或消失时保留调整并标记 PENDING，禁止把该房间空档当作可排考区间。普通编辑不能解除来源复核；独立 `rebindSource` 要求双方最新版本及理由，保留原稳定键和调整内容。明确撤销的来源可人工转为 LOCAL。
- OA 尚无已核实稳定课程 ID，本次 `sourceFingerprint` 仅用于精确来源版本匹配，不把可变内容哈希当作课程身份。迁移旧记录默认 UNVERIFIED；无法精确关联的旧记录保留待复核，避免将原手工课程默认为可删除 OA 数据。
- 教室按内部主键绑定，缺主键的来源按已核实校区别名 + 楼栋 + 教室号唯一定位；歧义不匹配首条。班牌 SN 改为字符串并按原样比较，不将教室 ID 或锁 ID 冒充 SN。教室列表不因多锁联表重复计数。
- 学校业务时间统一上海；显示区间为半开区间，结束瞬间解除，排程冲突保守包含相接端点。连续 `1-4` 保留中间教学课间；不连续多段分别计算。未配置单节边界或非法节次进入未知并阻止排考。默认仅保留仓库既有双节边界。
- 后端以同一只读一致快照、一个 `serverNow` 返回当前/未来事件、学校时区、版本、有效期、可信度问题、已知占用、边界及未启用门禁窗口预览。未来考试不占用现在；旧状态 2 不复活。已知冲突优先显示，来源未知不会算为空闲。
- 2D 卡片、统计、楼层汇总、详情、筛选和班牌消费同一快照。教学/考试/冲突/未知/空闲分别计数，占用率按已知占用的唯一教室计算；未来预约独立筛选。正常每 15 秒只读刷新，边界本地更新并触发刷新，恢复可见/联网重新读取；失败带抖动退避持续重试、过期/跨日降级未知，旧响应受版本检查保护。
- 排考表单实时只读加载所选日期的既有课程/考试，整批预览失败禁用提交，提交时服务端仍重新校验。预览范围最多 31 天，超过范围会明确拒绝预览。
- 班牌自动选择当前有效考试/课程，取消或结束后恢复排程展示；缺真实容量、签到/巡查实到或可靠请假来源时显示未知。合班事件去重但不凭缺少稳定班级身份的数据累加人数。OA 请假时段粒度未核实，班牌不将其冒充已确认历史请假；预计到课与实到分开。3D 页面明确标识演示。
- 门禁命令先持久化，再提交厂家 SDK，通过独立回执状态 `submitted/acknowledged/failed/unknown` 收敛；超时未知，不自动补发。命令保存原教室/设备/通道快照，登记事务再核实任务配置版本与真实绑定。未知命令阻断该任务新触发，管理员可在定时页面按现场依据明确确认原动作执行或未执行：只计一次或解除阻塞，不补发原命令。人工确认及理由留审计，命令确认不回写物理成功。设备观测独立 `observedAt`，超过两分钟或不支持通道则返回未知；查询失败不回传旧状态，绑定变更/新命令使旧观测失效。
- 管理端可按唯一教室主键维护真实锁及 1–4 通道，重复设备通道拒绝。每周任务使用真实 `taskId`，创建人来自认证用户，星期为整数 JSON 数组 `0=周一…6=周日`，通道与备注分离。次数正整数或 -1 无限，0 只表示耗尽。启停保留次数和通道，幂等回执才按真实 taskId 扣次数；多实例提交先锁任务行并核实待确认执行。旧配置 Job 触发时复核，绑定已改变不发送。
- Quartz 启动及每分钟对账数据库期望配置，按 taskId 创建/更新/撤销，单个坏任务不阻断其他任务，注册故障保留 DB 配置重试。按配置行版本持久化 pending/synced/failed 及成功时间，定时页面显示对账状态；旧版本对账不覆盖新配置。启停 SQL 不回写次数。上海 Cron + misfireDoNothing 不补发错过的历史动作。自动课表门禁保持关闭，仅生成保留窗口预览，不产生真实设备指令。
- 巡查按所选日期、节次、教室、班级和课程稳定键匹配；无可靠课程关联需要补录理由。新记录保存课程与区间快照；历史编辑保留原课程/快照/请假值，不调用今日 OA。已关联历史的日期、班级、节次和教室禁止改写。Excel 无请假来源保持 NULL，并记录人工导入快照；导入日期也按上海解析。
- 考试、课表写入、同步、来源复核、占用管理与门禁管理收紧服务端权限。移除考试/课表整路径白名单，显式规则优先于白名单；普通课表只读按认证用户学院过滤，LOCK_ONLY 不可读取。同步改 POST。排程、调整、绑定变更记录操作者、理由、前后内容和版本，当前问题可查询及自动复核关闭，历史保留。

## 二、接口与配置

路径沿用应用既有 `/api` 上下文，以下不再重复拼接前缀。

| 接口 | 契约 |
| --- | --- |
| `GET /classroomOccupancy/snapshot` | 管理端一致占用快照，可选 classroomId 或原样 boardSn |
| `GET /classroomOccupancy/schedule?classroomId=&from=&to=` | 所选 1–31 天有效安排，含跨日重叠考试和未知原因 |
| `GET /classroomOccupancy/issues` | 最近 200 条 OPEN 来源/绑定/时间/排程问题；独立修正后重新对账 |
| `POST /exam/preview?update=true/false` | 整批最终考试只读验证；成功不保存 |
| 考试单条及批量接口 | 统一服务；更新必须 rowVersion；状态修改使用普通更新接口 |
| `POST /courseSchedule/refresh` | 显式管理员同步，成功/失败/跳过均保留结构化回执 |
| `POST /courseSchedule/add` / `PUT /courseSchedule/update` | 本地课程、独立停调课；更新必须 rowVersion 和 changeReason |
| `POST /courseSchedule/rebindSource` | courseKey、rowVersion、sourceCourseKey、sourceRowVersion、reason；无来源键表示明确转 LOCAL |
| `GET /smart/lock/command/{commandId}` | 管理员读取持久化指令回执；acknowledged 不表示物理门已开 |
| `GET /smart/lock/commands?taskId=` / `POST /smart/lock/command/{commandId}/review` | 查询未知回执；复核必须明确 executed 与现场依据 reason，不发设备动作 |

配置入口：`SchoolScheduleProperties`；可复制 `soft_main/src/main/resources/application-schedule-example.yml` 的内容到实际环境配置。示例不会默认加载。初始 `coverage-confirmed=false`，首次迁移也不初始化可信成功来源，因此没有可靠依据时排考会被拒绝、房间主状态可能为未知。

启用可信空档判断前，需配置校方核实的 `coverage-start/coverage-end`、全部逐节 starts/ends、版本及校区别名，再成功发布完整 OA 来源。不能将 OA 返回行的最早/最晚日期自动等同完整学期覆盖。配置变更会改变实际策略指纹，旧覆盖随之失效。日同步、Quartz 时区显式上海；OA 可信度默认 24 小时，可按核实 SLA 调整。

统一入口为 [课表联动脚本目录说明](../../soft_main/src/sql/schedule-consistency/README.md)，仅保留预检、升级、核验及停用四个 SQL。

1. 在隔离测试库保存完整备份，运行只读 `soft_main/src/sql/schedule-consistency/01-preflight.sql`，确认字段、NULL/default、引擎、索引、重复位置及数据来源。
2. 维护窗口停止后端及排程写入，在实际应用数据库运行 `02-migrate.sql`。统一脚本按元数据跳过已有新增列/同名索引，只回填空值；DDL 有隐式提交，任何错误或 STOP 提示立即停止并核对进度。
3. 运行只读 `03-verify.sql`，检查必要字段、类型/NULL、唯一索引、状态行及待复核任务；既有新增表结构不完整仍须明确处理，再启动后端。
4. 旧课程默认 UNVERIFIED，不把历史手工记录冒充可清空的 OA 数据；历史 SN 前导零须从权威设备目录恢复。绑定/通道只采用唯一已核实来源，歧义不自动决定。
5. 不自动将旧零次改为 -1；需核实任务原语义、真实设备和通道后在管理端配置。配置正式作息和完整覆盖，成功同步后核查 OPEN 问题及调整，自动课表门禁保持关闭。
6. `04-disable-tasks.sql` 仅在需要停止排程/回退应用时人工执行，停用任务但保留新结构、字符串 SN、课程调整与审计；不撤销已发生的物理动作。恢复备份仍须联同所有业务与排程记录核对。
