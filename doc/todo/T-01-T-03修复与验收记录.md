## T-01：安全同步与多实例保护

- 保留先拉取、校验，再事务内 DELETE + 批量插入的流程。
- Redis 不可用时放弃本轮同步，不再降级为单机锁后继续写入。
- Redis 租约每 TTL/3 自动续期；续期失败或令牌不匹配后，当前租约永久失效。
- 拉取前、删除前、每批写入前和事务提交前验证持锁状态。
- 课表替换事务使用同一 JDBC 连接获取 MySQL `GET_LOCK` 会话锁；提交或回滚完成后才释放。
  该锁没有 Redis TTL，即使进程暂停、Redis 重启或租约过期，也不会让两个替换事务交叉写入。
  连接断开时，数据库释放会话锁并回滚该连接的未提交事务。
- 原课表行数和收缩保护校验放在数据库锁保护的事务内，避免使用并发替换前的过期计数。
- `saveBatch` 返回 false 同样视为失败并回滚；空白必要字段视为无效记录。
- 先释放分布式锁，再开放本实例下一轮同步。
- Lua 释放脚本迁至 `soft_common/src/main/resources/lua/release_lock.lua`，classpath 路径不变，
  避免公共模块测试或复用时依赖宿主模块提供脚本。

数据库锁使用现有 MySQL，无需建表或执行迁移。Redis 故障时会保留上一轮课表，待服务恢复后重试。

## T-03：整份 Excel 原子入库

- `doAfterAllAnalysed` 仅累计当前 sheet 的表头行数，不再提交数据库事务。
- `doReadAll()` 正常返回后，仅调用一次 `finishAndSave()`，统一校验全部 sheet 并在一个事务内入库。
  后续 sheet 的表头拒绝、行数超限、文件读取异常均发生在入库之前。
- 全文件行数上限在缓存下一行前检查，超限异常不会被行级容错吞掉。
- 批量写入抛异常或返回 false 时，全部 sheet 的已写入批次一起回滚。
- 入库数量统计覆盖全部 sheet，包含末尾空 sheet 的场景；表头数量为所有 sheet 表头行数之和。
- 错误明细携带工作表名称和 Excel 行号；EasyExcel 单元格转换异常也可登记为坏行。
- 日期严格校验，拒绝将 2 月 30 日等非法日期自动修正；人数拒绝负数、小数人数和整数溢出，
  保留 `40.0`、带单位等现有兼容输入。
- 保留默认跳过坏行策略；`fail-fast-on-error=true` 时整份文件有坏行即拒绝，零写入。
- 补充空文件名、扩展名大小写和精确文件大小校验。
