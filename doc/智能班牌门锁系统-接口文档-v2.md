### 0.2 鉴权说明

除白名单接口外，所有接口需在请求头携带 JWT：

```
Authorization: Bearer {token}
```

- 普通用户 token：`subject = 用户名,userId`
- **开锁专用 token（调整）**：`subject = lock_password:{timestamp}:{userId}`，Redis Key 由 **token 完整 SHA-256/MD5 摘要**生成（原实现取 token 前 8 位，存在碰撞，已修复）。
- 鉴权失败统一返回 JSON（调整后不再返回 HTML 错误页）：

```json
{ "code": 401, "msg": "未登录或登录已过期", "data": null }
```

### 0.3 统一响应结构

```json
{ "code": 0, "msg": "操作成功", "data": {} }
```

| 字段 | 类型 | 说明 |

| msg | string | 提示信息 |

## 1 门锁授权管理

### 1.1 查询用户在指定门锁上的操作权限

#### 基本信息

| 项目 | 值 |
|---|---|
| 接口路径 | `/api/lock/permission/check` |
| 接口描述 | 校验当前登录用户是否有权操作指定门锁（内部鉴权接口，前端也可用于按钮置灰） |
| 请求方式 | GET |
| Content-Type | application/x-www-form-urlencoded |

#### 请求参数

| 参数名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| lockId | int | 是 | 门锁 ID |

#### 请求示例

```
GET /api/lock/permission/check?lockId=12
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9...
```

#### 响应参数

| 参数名 | 类型 | 说明 |
|---|---|---|
| code | int | 0 成功 |
| msg | string | 提示信息 |
| data.hasPermission | boolean | 是否有权操作 |
| data.grantType | string | 授权来源：`role` 角色授权 / `user` 用户授权 / `schedule` 任课推导 / `none` 无 |
| data.reason | string | 说明文案 |

#### 响应示例

```json
{
  "code": 0,
  "msg": "操作成功",
  "data": {
    "hasPermission": true,
    "grantType": "schedule",
    "reason": "您是该教室当前课程的任课教师"
  }
}
```

#### 业务逻辑说明

1. 判定顺序：**角色授权 → 用户授权 → 任课关系推导**；
2. 角色授权：读 Redis Set `lock:perm:role:{roleId}`，判断 `lockId` 是否为成员；
3. 用户授权：读 Redis Hash `lock:perm:{userId}`，字段 `lockId` 值为 `"1"`；
4. 任课推导：`SELECT COUNT(1) FROM sys_course_schedule s JOIN sys_lock_info l ON l.JSH = s.JSH WHERE s.JGH = #{userId} AND l.lock_id = #{lockId}`（**只读现有表**）；
5. 任一命中即返回 `true`，并给出 `grantType`；
6. **不新增数据库表**，授权数据全部在 Redis。

### 1.3 授予/撤销门锁权限

#### 基本信息

| 项目 | 值 |
|---|---|
| 接口路径 | `/api/lock/permission/grant` |
| 接口描述 | 批量为角色或用户授予（或撤销）指定门锁的操作权限 |
| 请求方式 | POST |
| Content-Type | application/json |

#### 请求参数

| 参数名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| subjectType | string | 是 | 授权主体类型：`role` / `user` |
| subjectId | long | 是 | 角色 ID 或用户 ID |
| lockIds | array\<int\> | 是 | 门锁 ID 数组 |
| action | string | 是 | 操作：`grant` 授予 / `revoke` 撤销 |

#### 请求示例

```json
{
  "subjectType": "role",
  "subjectId": 3,
  "lockIds": [12, 13, 14],
  "action": "grant"
}
```

#### 响应参数

| 参数名 | 类型 | 说明 |
|---|---|---|
| data.affected | int | 实际变更条数 |
| data.action | string | 执行的动作 |

#### 响应示例

```json
{
  "code": 0,
  "msg": "操作成功",
  "data": { "affected": 3, "action": "grant" }
}
```

#### 业务逻辑说明

1. 校验操作人具备 `sys:lock:op` 权限（`@PreAuthorize`）；
2. `subjectType=role` → 写 Redis Set `lock:perm:role:{roleId}`（`SADD` / `SREM`）；
3. `subjectType=user` → 写 Redis Hash `lock:perm:{userId}`（`HSET` 值 `"1"` / `HDEL`）；
4. **不做 TTL**，通过主动删除保证变更即时生效；
5. 变更后写一条应用审计日志，并在 `sys_operation_log` 记录操作（`operation_method` 使用 `授权变更` 枚举码）；
6. **不新增数据库表**。

## 2 定时任务管理（调整与新增）

### 2.1 新增定时任务（调整）

#### 基本信息

| 项目 | 值 |
|---|---|
| 接口路径 | `/api/lock/timer/add` |
| 接口描述 | 为指定门锁新增一条定时开关锁任务（**调整**：支持同一门锁挂载多条任务） |
| 请求方式 | POST |
| Content-Type | application/json |

#### 请求参数

| 参数名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| lockId | int | 是 | 门锁 ID |
| timedOperation | int | 是 | 定时操作类型：1 开锁 / 2 关锁 |
| hour | int | 是 | 小时，0-23 |
| minute | int | 是 | 分钟，0-59 |
| countDay | array\<int\> | 是 | 生效星期，0=周日 … 6=周六；空数组表示每天 |
| loopCount | int | 否 | 执行次数：`-1` 不限次 / `0` 执行一次 / `N` 执行 N 次，默认 -1 |
| isLoop | int | 否 | 是否循环：1 是 / 0 否 |
| remarks | string | 否 | 备注 |

#### 请求示例

```json
{
  "lockId": 12,
  "timedOperation": 1,
  "hour": 8,
  "minute": 0,
  "countDay": [1, 2, 3, 4, 5],
  "loopCount": -1,
  "isLoop": 1,
  "remarks": "工作日早间开锁"
}
```

#### 响应参数

| 参数名 | 类型 | 说明 |
|---|---|---|
| data.taskId | long | 任务 ID |
| data.jobKey | string | Quartz JobKey，格式 `smartLockJob_{lockId}_{taskId}` |

#### 响应示例

```json
{
  "code": 0,
  "msg": "新增成功",
  "data": { "taskId": 1001, "jobKey": "smartLockJob_12_1001" }
}
```

#### 业务逻辑说明

1. **【调整】** JobKey 由原来的 `smartLockJob_{lockId}` 改为 `smartLockJob_{lockId}_{taskId}`，TriggerKey 同理；同一门锁可挂载多条任务，互不覆盖；
2. 不再无条件 `deleteJob`，仅对**同一 taskId** 做覆盖；
3. `countDay` 统一以**逗号分隔字符串**存入 `sys_schedule_task.count_day`（如 `1,2,3,4,5`），写入前经 `CountDayCodec.encode`；
4. `loopCount` 语义统一：`-1` 不限次、`0` 一次、`N>0` N 次；由 `LoopMode.modeOf()` 解释，四处入口行为一致；
5. 任务启用时初始化 Redis 计数器 `lock:task:count:{taskId}`；`-1` 不设；
6. 任务写入现有 `sys_schedule_task` 表，**不新增列**；`createdTime` 与 `updatedTime` 均赋当前时间（新增场景）。

### 2.2 修改定时任务状态（调整）

#### 基本信息

| 项目 | 值 |
|---|---|
| 接口路径 | `/api/lock/timer/updateStatus` |
| 接口描述 | 启用或暂停指定定时任务（**调整**：修复原实现重复调用导致的双写） |
| 请求方式 | POST |
| Content-Type | application/json |

#### 请求参数

| 参数名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| taskId | long | 是 | 任务 ID |
| taskStatus | int | 是 | 状态：1 启用 / 0 暂停 |

#### 请求示例

```json
{ "taskId": 1001, "taskStatus": 0 }
```

#### 响应参数

| 参数名 | 类型 | 说明 |
|---|---|---|
| code | int | 0 成功 |
| msg | string | 提示信息 |

#### 响应示例

```json
{ "code": 0, "msg": "操作成功", "data": null }
```

#### 业务逻辑说明

1. **【调整】** 原实现调用 `scheduleService.updateStatus` **两次**（L327、L331），现修正为单次；
2. DB 更新与 Quartz `pauseTrigger` / `resumeTrigger` 在同一方法内原子完成，保证一致；
3. 暂停时保留 `JobDetail`，仅暂停 Trigger，便于快速恢复；
4. 重启后由 `ScheduleLoad` 按 `task_status` 恢复，暂停中的任务不再被自动调度。

#### 基本信息

| 项目 | 值 |
|---|---|
| 接口路径 | `/api/lock/timer/logs` |
| 接口描述 | 查询指定定时任务的最近执行记录（**新增**） |
| 请求方式 | GET |
| Content-Type | application/x-www-form-urlencoded |

#### 请求参数

| 参数名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| taskId | long | 是 | 任务 ID |
| limit | int | 否 | 返回条数，默认 20，最大 200 |

#### 请求示例

```
GET /api/lock/timer/logs?taskId=1001&limit=20
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9...
```

#### 响应参数

| 参数名 | 类型 | 说明 |
|---|---|---|
| data.taskId | long | 任务 ID |
| data.remainCount | int | 剩余执行次数，-1 表示不限次 |
| data.logs | array | 执行记录（倒序） |
| data.logs[].executeTime | string | 执行时间 `yyyy-MM-dd HH:mm:ss` |
| data.logs[].success | boolean | 是否成功 |
| data.logs[].msg | string | 结果说明 |

#### 响应示例

```json
{
  "code": 0,
  "msg": "操作成功",
  "data": {
    "taskId": 1001,
    "remainCount": 7,
    "logs": [
      { "executeTime": "2026-03-20 08:00:00", "success": true,  "msg": "开锁成功" },
      { "executeTime": "2026-03-19 08:00:00", "success": false, "msg": "设备离线，未下发指令" }
    ]
  }
}
```

#### 业务逻辑说明

1. 剩余次数读 Redis `lock:task:count:{taskId}`（Redis 为权威计数，**原子 `DECREMENT`** 避免并发丢失更新）；
2. 执行记录读 Redis List `lock:task:log:{taskId}`（`LPUSH` + `LTRIM 0 199`，最多保留 200 条）；
3. 每次执行**无论成功失败均写入**记录，失败记录含原因；
4. **不新增数据库表**（原计划的 `sys_lock_task_log` 改由 Redis List 承载）；
5. Redis 丢失时剩余次数以 `sys_schedule_task.loop_count` 兜底重建。

1. 读取 `sys_course_schedule`（**现有表，只读**）中 `ZC = week` 的记录，取 `XQJ`(星期)、`SKJC`(节次)、`JSH`(教室)、`JGH`(教师)；
2. 按 `lock.class-periods` 配置把节次映射为起止时间；
3. 每条课表生成 **2 条任务**：课前 `openAheadMinutes` 开锁、课后 `closeDelayMinutes` 关锁；
4. 同一 `(JSH, XQJ, SKJC)` 组合去重，避免重复建任务；
5. 教室在 `sys_lock_info` 中找不到对应门锁时计入 `skipped`，并记录告警日志；
6. 生成的任务写入现有 `sys_schedule_task`，`task_details` 存 JSON 标记来源：
   `{"source":"courseSchedule","scheduleId":123,"week":5,"period":2}`；
7. `overwrite=true` 时先按 `task_details` 中 `source=courseSchedule` 清理旧任务（含 Quartz Job）；
8. **不新增数据库表**；节次时间表用配置文件承载。

3. `success` / `trigger` / `channel` 由 `remarks` 字段的 JSON 反序列化得到（**复用现有 text 列**）；
4. `success` 筛选在应用层过滤（因该字段不在数据库列中，无法走 SQL WHERE）；
5. `operationMethod` 使用统一枚举（D-06），不再散落魔法数字；
6. **取值兼容**：`remarks` 非 JSON（历史数据）时，`success` 返回 `null`，不报错。

### 6.2 导出开关记录（新增）

#### 基本信息

| 项目 | 值 |
|---|---|
| 接口路径 | `/api/lock/record/export` |
| 接口描述 | 按条件导出开关记录为 Excel（**新增**） |
| 请求方式 | GET |
| Content-Type | application/x-www-form-urlencoded |

#### 请求参数

| 参数名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| lockId | int | 否 | 门锁 ID |
| startTime | string | 是 | 开始时间 `yyyy-MM-dd HH:mm:ss` |
| endTime | string | 是 | 结束时间 `yyyy-MM-dd HH:mm:ss` |

#### 请求示例

```
GET /api/lock/record/export?lockId=12&startTime=2026-03-01 00:00:00&endTime=2026-03-20 23:59:59

```

#### 响应参数

返回 Excel 文件流（`application/vnd.ms-excel`），列：记录ID、门锁ID、教室、操作人、操作类型、操作时间、结果、触发来源。

#### 业务逻辑说明

1. 复用现有 `ExcelUtils` 工具类；
2. 导出上限 5 万条，超出提示收窄时间范围；
3. 单次导出写一条审计日志。

## 8 错误码说明

| 错误码 | 说明 | 处理建议 |
|---|---|---|
| 0 | 成功 | - |
| 400 | 参数错误 | 检查请求参数与格式 |
| 401 | 未登录或登录已过期 | 重新登录获取 Token |
| 403 | 无权限访问该资源 | 联系管理员分配权限 |
| 429 | 操作过于频繁 | 稍后重试（登录类 5 分钟） |
| 500 | 系统内部错误 | 携带 X-Trace-Id 联系运维 |
| 10001 | 无权限操作该设备 | 联系管理员授权 |
| 10002 | 设备不存在 | 检查 lockId |
| 10003 | 设备离线 | 检查设备网络 |
| 10004 | 开锁失败 | 设备未响应，可重试 |
| 10005 | 关锁失败 | 设备未响应，可重试 |
| 10006 | 指令超时 | 增大超时或检查网络 |
| 10007 | 通道号非法 | 检查 `remarks` 是否为 1-8 |
| 10008 | 重复请求（幂等拦截） | 勿重复提交 |
| 10009 | 设备 SN 已存在 | 勿重复录入 |
| 20001 | 密码未初始化 | 先调用初始化接口 |
| 20002 | 密码强度不足 | 按策略调整（6~12 位，两种以上字符） |
| 20003 | 原密码错误 | 重新输入 |
| 20004 | 台账已失效 | 重新获取开锁 Token |
| 20005 | 验证码错误或已过期 | 刷新验证码 |

| 30002 | 定时任务与门锁不匹配 | 检查 lockId |
| 30003 | Cron 表达式非法 | 检查 hour / minute / countDay |
| 30004 | 任务已达执行次数上限 | 调整 loopCount |
| 40001 | 课表同步失败 | 检查教学周次与课表数据 |
| 40002 | 该教室未绑定门锁 | 先在门锁管理中绑定 |
