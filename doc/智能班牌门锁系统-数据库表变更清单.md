## 二、基线核查（改表前必须先确认）

### 2.1 `sys_lock_info`：dump 与线上不一致（**高风险**）

**dump 中（`soft_manage_all.sql` 第 3487-3497 行）**：

```sql
CREATE TABLE `sys_lock_info`  (
  `lock_id` int NOT NULL AUTO_INCREMENT COMMENT '智能锁唯一标识符',
  `ip_address` text NULL COMMENT '智能锁IP地址',
  `sn_code` text NULL COMMENT '智能锁SN序列号',
  `port_number` int NULL DEFAULT NULL COMMENT '智能锁通信端口号',
  `switch_status` int NULL DEFAULT NULL COMMENT '当前开关状态（0-关 1-开）',
  `college` text NULL COMMENT '智能锁所属学院',
  `classroom` text NULL COMMENT '智能锁所属教室',
  `remarks` text NULL COMMENT '备注信息',
  PRIMARY KEY (`lock_id`) USING BTREE
)
```

**代码实际使用**（`SmartLockMapper.java` 第 19-125 行）：

```sql
-- 全部 5 处查询都在用 JSH 与 sys_classroom 联表
... l.JSH as classroomNumber ... LEFT JOIN sys_classroom c ON l.JSH COLLATE ... = c.JSH COLLATE ...
-- insert 也在写 JSH
INSERT INTO sys_lock_info(ip_address, sn_code, port_number, switch_status, JSH, remarks) VALUES(...)
```

| 字段 | dump | 代码 | 结论 |
|---|---|---|---|
| `JSH` | ❌ 无 | ✅ 全量使用 | **线上必须有，否则应用起不来** |
| `college` | ✅ 有 | ❌ 未使用 | 遗留列，线上是否存在待确认 |
| `classroom` | ✅ 有 | ❌ 未使用 | 遗留列，线上是否存在待确认 |
| `channel` | ❌ 无 | 间接用 `remarks` 当通道号 | 本次新增 |

**必须做的事**：先执行 `DESC sys_lock_info;` 与 DBA 核对线上真实结构。分两种情况：

- **情况 A：线上已有 `JSH`**（最可能）→ dump 文件滞后，需同步修正 dump；`V8` 直接加 `channel` 等新列即可。
- **情况 B：线上也无 `JSH`** → 当前代码根本跑不起来，说明线上是另一套。此时 `V8` 需先补 `JSH` 列再继续，并在文档中记录。

### 2.2 `sys_classroom.board_sn` 存在空串（**阻塞 V11**）

`sys_classroom.sql` 中确认存在 2 行空串：

| 行号 | id | board_sn |
|---|---|---|
| 61 | 308 | `''`（空字符串，非 NULL） |
| 63 | 310 | `''`（空字符串，非 NULL） |

**后果**：`ALTER TABLE sys_classroom ADD UNIQUE KEY uk_board_sn(board_sn);` 会立即报
`ERROR 1062 (23000): Duplicate entry '' for key 'sys_classroom.uk_board_sn'`。

**必须先执行 V13**：

```sql
UPDATE sys_classroom SET board_sn = NULL WHERE board_sn = '';
```

> MySQL 唯一索引允许多个 `NULL`，所以置为 `NULL` 后不会冲突。

### 2.3 `sys_operation_log` 无任何索引

当前只有主键 `switch_id`。按 `lock_id` / `user_id` / `operation_time` 查询全部走全表扫描；`user_id` 还是 `text` 类型（无法直接建普通索引，需前缀索引或改类型）。而 `SwitchRecordMapper.java` 中有 **9 处** SQL 指向该表，其中 **7 处是读接口**：

```java
selectAll()                  // L65  SELECT * FROM sys_operation_log
selectById()                 // L50
selectByLockId()             // L81
selectByUserId()             // L97
selectByTimeRange()          // L114
countByLockId()              // L131
countByUserId()              // L140
```

**结论**：`V9`（加列）与 `SwitchRecordMapper` 改造**必须同批次发布**，否则开锁记录页面会整体报错。

### 2.4 `sys_lock_password` 建表语句缺失

全仓库 `*.sql` 中**搜不到 `sys_lock_password` 的 `CREATE TABLE`**，但 `LockPassword.java` 标注了 `@TableName("sys_lock_password")`。说明该表是**手工在线上建的，已丢失建表脚本**。

**处理**：本次补一份完整建表脚本（**不执行 ALTER，仅在版本库补文件**），避免新环境部署时缺表。

## 三、新增表（7 张）

### 3.1 `sys_lock_permission` — 门锁授权表（V1）

**用途**：解决 S-01「无锁级授权」。支持**主体（用户/角色/部门）× 范围（单锁/分组/教室）× 通道 × 时间窗 × 有效期**五维授权。

| 字段 | 类型 | 允许空 | 默认 | 说明 |
|---|---|---|---|---|
| `id` | bigint | 否 | 自增 | 主键 |
| `subject_type` | varchar(16) | 否 | - | 授权主体类型：`user` / `role` / `dept` |
| `subject_id` | bigint | 否 | - | 主体 ID |
| `scope_type` | varchar(16) | 否 | - | 授权范围：`lock` 单锁 / `group` 分组 / `room` 教室 |
| `scope_id` | varchar(64) | 否 | - | 范围 ID（lock→lock_id；group→group_code；room→JSH） |
| `channel` | tinyint | 是 | NULL | 允许的通道号 1-8；NULL 表示全部通道 |
| `time_start` | time | 是 | NULL | 每日允许时段起；NULL 不限 |
| `time_end` | time | 是 | NULL | 每日允许时段止；NULL 不限 |
| `valid_from` | datetime | 是 | NULL | 授权生效时间；NULL 立即生效 |
| `valid_to` | datetime | 是 | NULL | 授权失效时间；NULL 永久 |
| `status` | tinyint | 否 | 1 | 1 启用 / 0 停用 |
| `create_by` | bigint | 是 | NULL | 创建人 |
| `create_time` | datetime | 否 | CURRENT_TIMESTAMP | 创建时间 |
| `update_time` | datetime | 否 | CURRENT_TIMESTAMP ON UPDATE | 更新时间 |
| `remarks` | varchar(255) | 是 | NULL | 备注（如"临时借用至 X 日"） |

**索引**：

| 索引名 | 字段 | 类型 | 用途 |
|---|---|---|---|
| PRIMARY | `id` | 主键 | - |
| `idx_subject` | `subject_type, subject_id` | 普通 | 按主体查授权 |
| `idx_scope` | `scope_type, scope_id` | 普通 | 按范围反查 |
| `uk_subject_scope` | `subject_type, subject_id, scope_type, scope_id, channel` | 唯一 | 防重复授权 |

> ⚠️ `channel` 可为 `NULL`，而 `NULL` 在唯一索引中不参与去重。因此**代码层需保证"全部通道"用 `0` 表示而非 `NULL`**，否则会出现重复记录。已在接口文档 v3 中约定。

**完整 DDL**：

```sql
CREATE TABLE `sys_lock_permission` (
  `id` bigint NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `subject_type` varchar(16) CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci NOT NULL COMMENT '授权主体类型：user/role/dept',
  `subject_id` bigint NOT NULL COMMENT '授权主体ID',
  `scope_type` varchar(16) CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci NOT NULL COMMENT '授权范围类型：lock/group/room',
  `scope_id` varchar(64) CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci NOT NULL COMMENT '授权范围ID',
  `channel` tinyint NOT NULL DEFAULT 0 COMMENT '允许通道号1-8；0表示全部通道',
  `time_start` time NULL DEFAULT NULL COMMENT '每日允许时段起（NULL不限）',
  `time_end` time NULL DEFAULT NULL COMMENT '每日允许时段止（NULL不限）',
  `valid_from` datetime NULL DEFAULT NULL COMMENT '授权生效时间（NULL立即生效）',
  `valid_to` datetime NULL DEFAULT NULL COMMENT '授权失效时间（NULL永久有效）',
  `status` tinyint NOT NULL DEFAULT 1 COMMENT '状态：1启用 0停用',
  `create_by` bigint NULL DEFAULT NULL COMMENT '创建人用户ID',
  `create_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `remarks` varchar(255) CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci NULL DEFAULT NULL COMMENT '备注',
  PRIMARY KEY (`id`) USING BTREE,
  UNIQUE INDEX `uk_subject_scope`(`subject_type` ASC, `subject_id` ASC, `scope_type` ASC, `scope_id` ASC, `channel` ASC) USING BTREE,
  INDEX `idx_subject`(`subject_type` ASC, `subject_id` ASC) USING BTREE,
  INDEX `idx_scope`(`scope_type` ASC, `scope_id` ASC) USING BTREE,
  INDEX `idx_valid_to`(`valid_to` ASC) USING BTREE
) ENGINE = InnoDB CHARACTER SET = utf8mb4 COLLATE = utf8mb4_general_ci COMMENT = '门锁授权表';
```

### 3.2 `sys_lock_card_record` — 刷卡流水表（V2）

**用途**：F-3-1。记录读卡器上报的每一笔刷卡事件（原方案想塞进 `sys_operation_log.remarks`，但那样无法按卡号检索）。

| 字段 | 类型 | 允许空 | 默认 | 说明 |
|---|---|---|---|---|
| `id` | bigint | 否 | 自增 | 主键 |
| `lock_id` | int | 否 | - | 门锁 ID |
| `card_no` | varchar(32) | 否 | - | 卡号 |
| `card_type` | tinyint | 是 | NULL | 卡类型：1 普通卡 / 2 管理卡 / 3 挂失卡 |
| `user_id` | int | 是 | NULL | 关联用户 ID（卡号匹配到人时） |
| `user_name` | varchar(32) | 是 | NULL | 冗余姓名（防用户改名后查不到） |
| `channel` | tinyint | 是 | NULL | 通道号 |
| `result_code` | int | 否 | 0 | 结果码：0 成功 / 非 0 失败 |
| `result_msg` | varchar(255) | 是 | NULL | 结果说明 |
| `swipe_time` | datetime | 否 | - | 刷卡时间（设备上报时间） |
| `receive_time` | datetime | 否 | CURRENT_TIMESTAMP | 平台接收时间 |
| `raw_data` | text | 是 | NULL | 原始报文（排障用） |

**索引**：

| 索引名 | 字段 | 用途 |
|---|---|---|
| PRIMARY | `id` | - |
| `idx_lock_time` | `lock_id, swipe_time` | 按锁+时间查流水（最常用） |
| `idx_card_no` | `card_no` | 按卡号追溯 |
| `idx_user_time` | `user_id, swipe_time` | 按人查流水 |

```sql
CREATE TABLE `sys_lock_card_record` (
  `id` bigint NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `lock_id` int NOT NULL COMMENT '门锁ID',
  `card_no` varchar(32) CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci NOT NULL COMMENT '卡号',
  `card_type` tinyint NULL DEFAULT NULL COMMENT '卡类型：1普通卡 2管理卡 3挂失卡',
  `user_id` int NULL DEFAULT NULL COMMENT '关联用户ID',
  `user_name` varchar(32) CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci NULL DEFAULT NULL COMMENT '冗余用户名',
  `channel` tinyint NULL DEFAULT NULL COMMENT '通道号',
  `result_code` int NOT NULL DEFAULT 0 COMMENT '结果码：0成功',
  `result_msg` varchar(255) CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci NULL DEFAULT NULL COMMENT '结果说明',
  `swipe_time` datetime NOT NULL COMMENT '刷卡时间',
  `receive_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '平台接收时间',
  `raw_data` text CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci NULL COMMENT '原始报文',
  PRIMARY KEY (`id`) USING BTREE,
  INDEX `idx_lock_time`(`lock_id` ASC, `swipe_time` ASC) USING BTREE,
  INDEX `idx_card_no`(`card_no` ASC) USING BTREE,
  INDEX `idx_user_time`(`user_id` ASC, `swipe_time` ASC) USING BTREE
) ENGINE = InnoDB CHARACTER SET = utf8mb4 COLLATE = utf8mb4_general_ci COMMENT = '门锁刷卡流水表';
```

> **数据量预估**：按 500 台锁、日均 20 次刷卡计，约 1 万条/天、365 万条/年。建议**保留 12 个月**，用定时任务按月归档删除。

```sql
SET channel = CAST(remarks AS UNSIGNED)
WHERE remarks IS NOT NULL AND remarks REGEXP '^[1-8]$';

-- 步骤 2：非法值统一为默认通道 1
UPDATE sys_lock_info
SET channel = 1
WHERE channel IS NULL OR channel < 1 OR channel > 8;

-- 步骤 3：清掉 remarks 中的旧通道号（保留真正的备注文本）
UPDATE sys_lock_info
SET remarks = NULL
WHERE remarks REGEXP '^[1-8]$';

-- 步骤 4：核对
SELECT lock_id, remarks, channel FROM sys_lock_info;
```
