## 智能班牌门锁系统：代码与业务逻辑体检（只读分析，未改动代码）

### 门锁子系统代码地图
- Controller：`SamrtLockController`（/smart/lock，549 行，含设备管理/远程开关/定时任务/状态查询）、
  `LockPasswordController`（/lock，开锁密码登录 + 设置）、`SwitchRecordController`（/smart，开关记录 CRUD + 统计）
- 设备通信：`SmartLockSwitch`（openDoor/closeDoor/queryDoorStatus）、`CloseDoorCommand`、`SearchDeviceCommand`、
  `CommandAllocator`、`MyConnectorEvent`、`NetworkInfo`
- 调度：`QuartzConfig`（Cron 生成 + JobDetail/Trigger）、`SmartLockQuartz`（Job）、`ScheduleLoad`（启动恢复任务）
- SDK：`soft_main/lib/DoorAccessIO.jar`（Door8800 / Door89H，579 个类）
- 表：`sys_lock_info`(lock_id/ip_address/sn_code/port_number/switch_status/JSH/remarks)、
  `sys_classroom`(board_sn/JSH/SKDD/XQMC/JZWMC/floor)、
  `sys_operation_log`(switch_id/lock_id/user_id/operation_method/operation_time)、
  `sys_schedule_task`、`sys_lock_password`（全局单密码，BCrypt）

### 关键结论
1. **SDK 利用率极低**：仅用了 4 个命令（SearchEquptOnNetNum / HoldDoor / CloseDoor / ReadWorkStatus），
   刷卡流水(ReadTransactionDatabase)、卡片下发(WriteCardListBySequence)、时段组(AddTimeGroup)、
   节假日(AddHoliday)、门磁/防盗/烟雾告警、消防联动、BeginWatch 实时事件、
   校时(WriteTime)、改 IP(WriteTCPSetting)、常开常闭(LockDoor/UnlockDoor) 全部未接。
2. **无授权模型**：`/smart/lock/updateSwitchStatus` 只要登录就能开任意锁（无 @PreAuthorize，19 处注解不在这两个 Controller）。
3. **全局开锁密码是单密码**且无频率限制/验证码（`/lock/login` 在白名单，CaptchaFilter 只拦 `/api/login`），
   暴力破解即等于全校开门；日志用 userId=-1 记，无法追溯到人。
4. **开锁指令结果不校验**：`FuturePrice` 创建后从未 join，异常被吞，接口返回"开锁成功"但门可能没开；
   先写库后发指令，且 `queryStatus` 异步回写会造成状态漂移。
5. **定时任务模型受限**：JobKey 固定为 `smartLockJob_{lockId}`，一把锁只能有一个任务；
   `loopCount` 在 addTimer(`>-2`) 与 setTimerTask(`>0`) 判断不一致；无执行历史/失败重试。
6. **有桥未搭**：项目已有 `sys_course_schedule`（每天 3 点从 OA 拉课表，含 ZC 周次字段）和完整审批流
   (`Flow`/`FlowTask`/`Construct`)，但**都没和门锁打通**——按课表自动开关锁、借用审批→临时授权 完全没做。
7. **SQL dump 与线上表结构不同步**：`soft_main/src/sql/*.sql` 里 `sys_lock_info` 仍是老的
   college/classroom 列（代码已改用 JSH），且**没有 sys_lock_password 建表语句**。
8. 其他：`SmartLockSwitch` static 状态与 static future 存在并发污染；Controller 单例字段 `devicesList`；
   `sys_operation_log` 无任何索引、user_id 是 text；通信密码 `FFFFFFFF` 硬编码；全项目用 System.out.println。

### 实施文档中确定的关键技术决策
- **授权模型**：`sys_lock_permission`（主体×范围×通道×时间窗×有效期），统一入口 `LockPermissionService#decide`，判定优先级 = 灰度开关 → 超级管理员 → 管理员角色 → 授权表 → **排课回退** → 拒绝并落审计。
- **排课回退用 `SKRQ`（上课日期 yyyyMMdd）而非 `ZC`+`XQJ`**：教务已把单双周/调课/停课算好烘焙进 SKRQ，P0 无需实现周历推算；周历留给 IMP-11 生成任务时用（新增 `sys_term_calendar`）。
- **一人一码必须带定位标识**：BCrypt 单向不可反查，故 `/lock/login` 拆两种模式 —— 一人一码走 `username` 定位 `owner_user_id`，场所码走 `boardSn` 定位 scope。
- **SDK 回执校验关键细节**：`ConnectorAllocator` 是全局单例，回调可能由**别的命令**触发 → 必须加 `if (c != cmd) return;` 过滤，否则并发开锁会串号。
- **隐藏内存泄漏**：现有代码每次 `openDoor`/`queryDoorStatus` 都 `allocator.AddListener(new MyConnectorEvent())` → 监听器列表无限增长，改为 `@PostConstruct` 一次性注册。
- **定时任务一锁多任务（R-10）**：JobKey 改为 `smartLockJob_{lockId}_{taskId}`。
- **`countDay` 统一为无空格 JSON `"[0,1,2]"`**，配套 `encodeCountDay`/`decodeCountDay`，并清洗历史 `Arrays.toString` 带空格数据。
- **`loopCount` 统一语义**：`-1 = 无限`、`>0 = 剩余次数`，抽唯一入口 `QuartzConfig#resolveTrigger`。
- **状态回写只写状态列**：`queryDoorStatus` 的 `update(targetLockInfo)`（全字段覆盖）改为 `updateSwitchStatus(lockId, status)`，并加 `last_command_time` 防抖动。
- **上线策略**：`lock.auth.enabled` 灰度开关，首次上线先 false 观察 1 天再置 true；老表 `sys_operation_log` 改名归档而非迁移数据。
- **作息时间表默认节次映射**（待教务确认）：1-2=08:00-09:40 / 3-4=10:00-11:40 / 5-6=14:00-15:40 / 7-8=16:00-17:40 / 9-10=19:00-20:40，课前 10 分钟开、课后 10 分钟关。

### 本轮确定的关键技术决策（不改表前提下）

- **四类"必须新表"的能力全部改由 Redis 承载**：`sys_lock_permission` → `lock:perm:{userId}`(Hash) + `lock:perm:role:{roleId}`(Set)；`sys_lock_device_status` → `lock:heartbeat:{lockId}`(TTL 90s) + `lock:status:{lockId}`；`sys_lock_task_log` → `lock:task:log:{taskId}`(List,LPUSH+LTRIM 200) + `lock:task:count:{taskId}`(原子 DECREMENT)；密码分表 → `lock:pwd:scoped:{scope}`。
- **扩展字段挤进现有 text 列**：`sys_operation_log.remarks` 存 JSON `{success,trigger,channel,cardNo,resultCode}`；`sys_schedule_task.task_details` 存 `{source:"courseSchedule",scheduleId,week}`。**代价**：卡号/结果无法走 SQL WHERE，筛选需应用层过滤。
- **实体注解不属"改表"**：`@TableName` / `@TableField(exist=false)` / `@TableId` 修正均可做（仅 ORM 层）。
- **`sys_menu` 数据订正属"改数据"非"改结构"**，仍给出「数据也不许动时在代码层兼容双权限码」的备选。
- **课表联动节次时间表用配置文件** `lock.class-periods[].{index,start,end}`，不建表。
- **R-01 修复原则**：所有门状态变更改为「**先执行、后落库**」，`openDoor` 由 `void` 改 `boolean` 并阻塞等待 Future（总超时 8s）。
- **R-10 JobKey**：`smartLockJob_{lockId}_{taskId}`。
- **R-14 countDay 格式**：本轮改为**逗号分隔 `"1,2,3"`**（与第三轮的 JSON `"[0,1,2]"` 不同），解码器 `CountDayCodec.decode` 需兼容旧格式 `[1, 2, 3]`（带空格）与纯数字串 `1234567`。
- **R-11 loopCount 语义**：`-1` 不限 / `0` 一次 / `N>0` N 次，统一入口 `LoopMode.modeOf()`。
- **唯一无法绕过项**：D-12（dump 与线上不同步）—— 只修 dump 文本文件；若线上真无 `JSH` 列则属结构性阻塞，需升级决策。
- **未落库数据的可接受取舍**：Redis 丢失后授权可重建、心跳丢失、密码 scope 失效（DB 全局密码兜底）；任务明细仅留最近 200 条。
