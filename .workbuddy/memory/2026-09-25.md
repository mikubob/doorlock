## 规范化 ApifoxHelper 注释（Controller + 实体/参数类）

**背景**：团队用 ApifoxHelper 生成接口文档到 Apifox，但大量接口在 Apifox 里显示英文方法名（captcha / getUserInfo / pass…），目录名也显示英文类名。

**根因**：
- ApifoxHelper 只解析 Javadoc 块注释 `/** */`，**不解析行注释 `//`**。
- 目录名 = 类级 Javadoc 第一行；接口名 = 方法级 Javadoc 第一行；`@param`/`@return` → 参数与响应说明。
- 原代码大量使用 `//` 行注释（AuthController、RoleController、MenuController、ProjectController 等），插件读不到 → 回退为方法名。

**改动**（仅注释，无逻辑变更）：
- `soft_main/.../controller/` 下 19 个 Controller 全部改为 Javadoc：类级中文模块名 + 方法级中文接口名 + `@param`/`@return` 说明。其中 14 个原为行注释或无注释。
- 统一了 5 个原本已中文但带 `Controller`/`控制器` 后缀的目录名 → 去掉后缀（如「考试信息Controller」→「考试信息管理」「开关记录控制器」→「开关记录管理」）。
- 「首页数据管理」「角色权限管理」「菜单管理」「认证授权与用户管理」「项目管理」「审批流程管理」「智能门锁管理」「教学巡查管理」「课程管理」「建设项目管理」「学生信息管理」「专业方向管理」「教学画像统计」「测试接口」「课程安排管理」「教室信息管理」「开考信息管理」「开锁密码管理」「开关记录管理」。
- `soft_model/.../model|params|vo|dto/` 下把请求体相关类的字段 `//` 注释改为 Javadoc：User、Role、Menu、CheckResult、Flow、ResultItem、Result、Project、ProjectItem、Task、Construct、ConstructResult、Course、ScheduleTask、StudentInfo、MajorDetails；params 全部；关键 dto/vo（QueryPage、UserQueryVo、UserSave、UserVo、StringParam、ConFileParam、FlowParam、NoticeQueryParam、NoticeParam、HomeParam、ProjectParam、ProjectQueryParam、ApproveParam、UserParam、ConstructQueryParam、TeachHomeParam、TeachAnalysistHomeParam、UserPasswordParam、SubTaskDto、SubTaskIdDto、ScheduleTaskDto、AdmissionDto、BatchAdmitDto、ProjectItemVo、ProjectVo、ResultVo、StudentInfoVo、CheckResultDataVo、CheckResultByTeacherDataVo）。
- 顺带修正笔误：MenuController「返沪权限」→「返回权限」。

**构建验证**：`JAVA_HOME=D:/CodeEnvironment/JDK1.8 mvn -B compile -DskipTests` → BUILD SUCCESS。

**环境要点（重要）**：
- 项目 `java.version=1.8`，**必须用 JDK 1.8 编译**（`D:\CodeEnvironment\JDK1.8`）。系统默认 JAVA_HOME 是 JDK 21，Lombok 会报 `NoSuchFieldError: JCTree$JCImport.qualid`。
- `-o` 离线模式会缺 maven-resources-plugin 依赖，需联网构建。

**遗留（可选）**：纯响应类仍缺字段注释——FlowTask、Info、Message、Notice、ResultExtend、RoleMenu、UserRole 及部分 vo（ApproveVo、FlowVo、FlowStatus 等）。

**代码问题记录（未改动）**：类名 `SamrtLockController` 拼写错误（应为 SmartLock）；AuthController 存在两个同名重载 `getUserInfo`；ScheduleController 有 `/debug/userInfo` 临时调试接口。

## 第二轮：全项目 `//` 文档注释清零（// → Javadoc）

**诉求**：用户指出「还存在原来使用 `//` 注释的没有改成 javadoc 的注释形式」。

**范围界定（关键）**：只转「类成员级」的文档注释（字段 / 方法 / 类的说明），**不动方法体内的实现注释**。判定标准 = 花括号深度 ≤ 1。

**补充完成的改动**：

**踩坑**：
- `ClearFileConfig` 里 `// 0 0 0 1 */3 ? 每三个月执行一次` 转 Javadoc 后，文本中的 `*/` **提前闭合注释导致编译失败** → 已改写文案避开。
- `StudentInfoServiceImpl` 一处方法体内注释被脚本误判转成 Javadoc（`if` 前）→ 已改回 `//`。
- Windows 下 Write/Edit 偶发 `EBUSY: resource busy or locked`，直接重试即可。

**最终验证**：
- `scan_members.py` → **0 处**类成员级 `//` 文档注释。
- `verify_comments.py` → 无 `*/` 破坏、无方法体误转（仅剩 SearchDeviceCommand / CloseDoorCommand / CommandAllocator / RedisCacheAop 等方法内匿名类的**原有**合法 Javadoc）。
